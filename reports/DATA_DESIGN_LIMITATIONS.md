# 데이터·통계 설계 독립 점검

이 문서는 테스트 결과를 이용한 튜닝 없이 데이터 생성 규칙과 통계 코드를 점검한 기록이다. 현재 벤치마크는 `controlled-truth-v1`이며 제한된 합성 참·거짓 판단 과제다. 관찰된 대응은 자연어 개념 전체의 보존이나 단일 의미성의 증거로 확대 해석할 수 없다.

## 결과 산출 전 군집 단위 교정

초기 구현은 개념×wrapper를 군집으로 지정했다. 그러나 같은 여섯 wrapper가 네 개념에 반복되므로 이를 24개의 독립 템플릿처럼 부트스트랩하면 의존성을 과소평가한다. `group_id`를 **개념 전체를 묶는 wrapper 단위**로 교정했다. 각 분할에는 최대 여섯 군집만 있다. 하나의 wrapper를 재표집할 때 그 wrapper에 속한 네 개념과 대응 참·거짓 문항을 함께 재표집한다.

교정은 군집 메타데이터와 검증에만 적용했다. 프롬프트, 정답, seed, 분할 소속은 바꾸지 않았다. 레코드 전체 해시에는 군집 메타데이터가 포함되므로 새 manifest의 해시는 기존 manifest와 달라질 수 있다. 기존 저장본은 같은 텍스트를 유지한 채 새 군집 규칙으로 명시적으로 재생성해야 한다.

`cluster_bootstrap`은 wrapper 평균들의 동일 가중 평균을 추정한다. prompt 수가 많은 wrapper에 더 큰 가중치를 주지 않는다. 95% percentile 구간은 **탐색적 구간**이다. 여섯 군집은 안정적인 모집단 추론에 부족하며, 의미 문법과 모델 seed의 불확실성까지 표현하지 않는다. 대응 sign-flip 검정은 wrapper별 방법 교환 가능성을 가정한다. 여섯 군집에서 양측 exact p값의 최소치는 2/64=0.03125이므로 다중 비교 후 강한 결론을 내리기 어렵다. 뉴런 수나 prompt 수를 독립 군집 수처럼 해석하면 안 된다.

## 확인된 표면적 우회 경로

| 개념 | 현재 생성 규칙 | 대체 설명 / 우회 경로 | 허용되는 해석 |
|---|---|---|---|
| 산술 | 거짓 합계는 실제 합에서 ±1 | 짝홀성 또는 간단한 modular feature만으로 참·거짓을 나눌 수 있음 | 합계 문장의 제한된 진위 판단 |
| 수 비교 | 같은 피연산자에서 greater/less를 교체 | 관계 단어 및 자릿수·첫 숫자 단서가 작동할 수 있음; 등호·동일값은 없음 | 부등식 방향 판단에 대한 제한적 대응 |
| 부정 | 하나의 속성만 가진 객체에 대해 “그 속성이 아니다” 판단; 거짓/참은 동일/다른 속성 | property 토큰의 동일성 비교만으로 해결 가능; 다른 속성은 숫자 suffix가 +1인 이름이라 추가 단서가 존재 | 명시된 사실에 대한 속성 동일성·부정 판단 |
| 괄호 | 올바른 괄호열의 닫는 기호 하나를 여는 기호로 교체 | 모든 invalid 문항은 여는/닫는 기호 수가 달라 **개수만 세어도 해결 가능** | 제한된 괄호 진위 판단; 계층적 syntax 학습으로 주장 불가 |

이 문제들을 D3/D4 결과를 본 뒤 조용히 수정하지 않는다. 더 강한 벤치마크는 새 버전과 새로운 최종 테스트셋으로 수행해야 한다. 예를 들어 산술에는 다양한 오답 거리와 같은 parity 오답, 부정에는 숫자 없는 임의 속성명과 동일성 대조 과제, 괄호에는 기호별 개수는 같지만 순서·종류가 잘못된 예제가 필요하다.

## 분할·의미 검증과 남은 한계

- 완전한 wrapper 문장, prompt, 순서 없는 숫자 피연산자 조합, 부정의 사실 객체·속성 조합, 올바른 괄호열을 분할 간 분리한다. 숫자 범위는 모든 분할에서 0–63으로 같다.
- 평가 문장의 wrapper는 새롭지만 내부 의미 문장 문법은 공유한다. 이를 완전한 문법 분포 외 일반화라고 부르지 않는다.
- 정답은 yes/no 두 후보의 전체 continuation 확률로 평가해야 한다. truth label은 concept membership과 별개다. 개념 간 활성 차이는 어휘·길이 차이일 수도 있다.
- 개별 산술·비교·부정·괄호 문항의 truth label을 생성 코드와 별도의 계산·파싱 경로로 검증하는 테스트가 있다. 대응 문항의 개념·wrapper·내용 key 보존도 검증한다.
- 괄호 개수 shortcut이 실제로 모든 문항을 해결함을 검증 테스트로 노출했다. 검증 통과는 이 한계를 없애지 않는다.
- 모델 간 토큰 수·답변 길이 차이와 실제 과제 능력은 별도로 보고해야 한다. 낮은 능력에서 대응이 없다는 이유로 기능 보존 가설을 기각하면 안 된다.
- 자연어 atlas용 독립 공개 코퍼스는 이 생성기에 포함되지 않았다. 합성 결과와 자연어 결과를 구분해야 한다.
- 단일 모델 쌍과 소수 초기화 seed에서는 모집단 모델 간 보편성에 관한 추론이 불가능하다. layer·neuron 수가 이를 대체하지 않는다.

## 재실행 규칙

테스트셋을 사용한 후보 재선택·임계값 조정·정렬 방법 선택은 금지한다. 통계 군집 오기와 계산 오류를 고치는 경우 교정 전후 분석 버전과 이유를 남긴다. 과제 생성 규칙을 바꾸려면 새 데이터 버전을 만들고 기존 결과를 보존한다.
